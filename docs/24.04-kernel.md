```text
/dtbs/6.1.0-odroid-arm64/rockchip/rk3566-odroid-m1s.dtb
```

Relevant decompiled DTB node:

```dts
usb@fcc00000 {
    compatible = "rockchip,rk3568-dwc3\0snps,dwc3";
    reg = <0x00 0xfcc00000 0x00 0x400000>;
    dr_mode = "otg";
    status = "okay";
    maximum-speed = "high-speed";
};
```

This means the board description exposes the DWC3 controller in OTG mode. It does not by itself prove that HID gadget works; the kernel still needs the HID gadget functions.

## Stock 24.04 kernel config finding

Relevant config values from `config-6.1.0-odroid-arm64`:

```text
CONFIG_USB_OTG=y
CONFIG_USB_DWC3=y
# CONFIG_USB_DWC3_HOST is not set
# CONFIG_USB_DWC3_GADGET is not set
CONFIG_USB_DWC3_DUAL_ROLE=y
CONFIG_USB_GADGET=y
CONFIG_USB_LIBCOMPOSITE=m
# CONFIG_USB_CONFIGFS is not set
# CONFIG_USB_G_HID is not set
CONFIG_TYPEC=m
CONFIG_USB_ROLE_SWITCH=y
```

`CONFIG_USB_F_HID` and `CONFIG_USB_CONFIGFS_F_HID` were not present in the config.

## Consequence

The stock 24.04 image is not enough for the HID keyboard/mouse part of a remote KVM. It can still be the primary OS base if the project supplies or documents a KVM-enabled ODROID kernel.

Minimum kernel options for the preferred configfs path:

```text
CONFIG_USB_GADGET=y
CONFIG_USB_LIBCOMPOSITE=m or y
CONFIG_USB_CONFIGFS=m or y
CONFIG_USB_CONFIGFS_F_HID=y
CONFIG_USB_F_HID=m or y
```

Useful legacy option:

```text
CONFIG_USB_G_HID=m or y
```

## HID-enabled 24.04 kernel preparation path

Status: **planned and unverified**.

The project should not publish or recommend a kernel package until it has been built, installed, booted, and verified on a real ODROID M1S. The current safe path is a checklist for producing a HID-enabled ODROID 24.04 kernel, not a supported binary release.

### Required config delta

Starting from the ODROID 24.04 `6.1.0-odroid-arm64` config, the minimum HID gadget delta is:

```text
CONFIG_USB_CONFIGFS=m or y
CONFIG_USB_CONFIGFS_F_HID=y
CONFIG_USB_F_HID=m or y
```

Keep these already-present prerequisites enabled:

```text
CONFIG_USB_GADGET=y
CONFIG_USB_LIBCOMPOSITE=m or y
CONFIG_USB_DWC3=y
CONFIG_USB_DWC3_DUAL_ROLE=y
CONFIG_USB_ROLE_SWITCH=y
```

Optional legacy test support:

```text
CONFIG_USB_G_HID=m or y
```

### Build strategy

The preferred build strategy is:

1. Start from the ODROID M1S 24.04 kernel source and packaging branch that produced `6.1.0-odroid-arm64`.
2. Import or reproduce the stock `config-6.1.0-odroid-arm64` as the baseline.
3. Apply only the HID gadget config delta above.
4. Build kernel image, modules, DTBs, and Debian packages using the ODROID packaging flow.
5. Install on a test SD/eMMC image, not a user's only working boot media.
6. Boot the real M1S and record `uname -a`, `/boot/config-$(uname -r)`, `/sys/class/udc`, and `scripts/verify-hid-support.sh` output.
7. Only after that, document the exact source commit, config diff, package names, checksums, and install/rollback steps.

### Verification gates before calling 24.04 supported

24.04 HID support remains **blocked** until all of these are true on real hardware:

```bash
grep -E 'CONFIG_USB_CONFIGFS=|CONFIG_USB_CONFIGFS_F_HID=|CONFIG_USB_F_HID=' /boot/config-$(uname -r)
sudo ./scripts/verify-hid-support.sh
ls /sys/class/udc
sudo ./scripts/setup-hid-gadget.sh
ls -l /dev/hidg0 /dev/hidg1
sudo ./scripts/teardown-hid-gadget.sh
```

The support matrix may say `24.04 userspace base + HID-enabled kernel required`, but it must not say `stock 24.04 supported` unless the stock kernel config changes and is re-verified.

### Rollback requirement

Any future kernel install guide must include a rollback path before it is considered safe for users:

- keep the previous bootable kernel installed;
- document bootloader entry selection or recovery media steps;
- record package removal/downgrade commands;
- never require network-only recovery for a headless KVM appliance.
